# Starknet contracts

| Package | What it is |
|---|---|
| `pf_batch_k10_verifier` | Generated by Garaga (`ultra_keccak_zk_honk`) from the verification key of `noir/batch_k10`. Do not edit it; regenerate it. It is tested through `pf_registry`. |
| `pf_registry` | Calls the verifier, accepts a proof only if its authority key hash is listed by the registry owner, refuses a batch if any of its nullifiers was seen before, and records what was proved. It never stores invoice data. |

```sh
. tools/toolchain.env
(cd starknet/pf_registry && snforge test)      # 6 tests against a real 10-invoice proof
sh tools/starknet/refresh_fixture.sh           # after any circuit change
sh tools/starknet/devnet_demo.sh               # the whole flow on a local network
```

The verifier embeds the circuit's verification key. After any change under `noir/pf_xmldsig`,
`noir/pf_efi` or `noir/batch_k10`, run `refresh_fixture.sh`, otherwise the contract rejects proofs
of the new circuit.

On a local network (starknet-devnet) the flow runs end to end: declare, deploy, list the authority
key, submit a 10-invoice proof (accepted, about 864M L2 gas in one transaction), read the record
back, submit the same proof again (refused with `invoice already presented`). Nothing is deployed
to a public network. Whether the single transaction fits a public network's per-transaction limit
has not been measured.
