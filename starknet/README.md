# Starknet contracts

| Package | What it is |
|---|---|
| `pf_batch_k10_verifier` | Generated by Garaga (`ultra_keccak_zk_honk`) from the verification key of `noir/batch_k10`. |
| `pf_agg_top_verifier` | Generated the same way from `noir/agg_top`, the final proof of an aggregate. |
| `pf_registry` | Calls the right verifier, accepts a proof only if its authority key hash is listed by the registry owner, refuses a presentation whose nullifiers were seen before, and records what was proved. For an aggregate it also checks that the proof was built from the leaf, node and sorted-list circuits the registry was deployed with, and takes the number of invoices from the proof. It never stores invoice data. |

Do not edit the generated packages; regenerate them. They are tested through `pf_registry`.

```sh
. tools/toolchain.env
(cd starknet/pf_registry && snforge test)      # 13 tests against real proofs
sh tools/starknet/refresh_fixture.sh           # after any circuit change
sh tools/starknet/devnet_demo.sh               # the whole flow on a local network
```

A verifier embeds its circuit's verification key. After any change under `noir/`, run
`refresh_fixture.sh`, otherwise the contracts reject proofs of the new circuits.

On a local network (starknet-devnet) the flow runs end to end for both kinds of proof: declare,
deploy, list the authority key, submit (accepted: about 862M L2 gas for the batch of 10, 821M for
an aggregate of 25), submit the same proof again (refused with `invoice already presented`). The
cost of an aggregate does not depend on how many invoices it covers. Starknet documents a limit of
1.11 * 10^9 L2 gas per transaction. Nothing is deployed to a public network.
