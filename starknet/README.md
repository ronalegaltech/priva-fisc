# Starknet contracts

| Package | What it is |
|---|---|
| `pf_batch_k10_verifier` | Generated by Garaga (`ultra_keccak_zk_honk`) from the verification key of `noir/batch_k10`. |
| `pf_agg_root_k10_b2_verifier` | Generated the same way from `noir/agg_root_k10_b2` (20 invoices: two leaves of 10 and a root). |
| `pf_registry` | Calls the right verifier, accepts a proof only if its authority key hash is listed by the registry owner, refuses a presentation whose nullifiers were seen before, and records what was proved. For an aggregate it also checks that the proof was built from the leaf circuit the registry was deployed with. It never stores invoice data. |

Do not edit the generated packages; regenerate them. They are tested through `pf_registry`.

```sh
. tools/toolchain.env
(cd starknet/pf_registry && snforge test)      # 11 tests against real proofs
sh tools/starknet/refresh_fixture.sh           # after any circuit change
sh tools/starknet/devnet_demo.sh               # the whole flow on a local network
```

A verifier embeds its circuit's verification key. After any change under `noir/`, run
`refresh_fixture.sh`, otherwise the contracts reject proofs of the new circuits.

On a local network (starknet-devnet) the flow runs end to end for both kinds of proof: declare,
deploy, list the authority key, submit (accepted: about 863M L2 gas for the batch of 10, 820M for
the aggregate of 20), submit the same proof again (refused with `invoice already presented`).
Starknet documents a limit of 1.11 * 10^9 L2 gas per transaction. Nothing is deployed to a public
network.
