# Starknet contracts

| Package | What it is |
|---|---|
| `pf_batch_k10_verifier` | Generated by Garaga (`ultra_keccak_zk_honk`) from the verification key of `noir/batch_k10`. |
| `pf_agg_top_verifier` | Generated the same way from `noir/agg_top`, the final proof of an aggregate. |
| `pf_registry` | Calls the right verifier, accepts a proof only if its authority key hash is listed by the registry owner, refuses a presentation whose nullifiers were seen before, and records what was proved. A context takes one kind of proof, batches or aggregates, because their nullifiers cannot be compared with each other. For an aggregate it also checks that the proof was built from the leaf, node and sorted-list circuits the registry was deployed with, and takes the number of invoices from the proof. It never stores invoice data. |

Do not edit the generated packages; regenerate them. They are tested through `pf_registry`.

```sh
. tools/toolchain.env
(cd starknet/pf_registry && snforge test)      # 16 tests against real proofs
sh tools/starknet/refresh_fixture.sh           # after any circuit change
sh tools/starknet/devnet_demo.sh               # the whole flow on a local network
sh tools/starknet/sepolia_demo.sh              # the same flow on Starknet Sepolia; needs a funded account
```

A verifier embeds its circuit's verification key. After any change under `noir/`, run
`refresh_fixture.sh`, otherwise the contracts reject proofs of the new circuits.

On a local network (starknet-devnet) the flow runs end to end for both kinds of proof: declare,
deploy, list the authority key, submit (accepted: about 865M L2 gas for the batch of 10, 822M for
an aggregate of 25), submit the same proof again (refused with `invoice already presented`). The
cost of an aggregate does not depend on how many invoices it covers. Starknet documents a limit of
1.11 * 10^9 L2 gas per transaction. Nothing is deployed to a public network.

The same flow is scripted for the public test network in `tools/starknet/sepolia_demo.sh` and has
been rehearsed on a local network, including deploying the account. Declaring is most of the cost:
about 1.9 * 10^9 L2 gas for the ECIP helper, 4.8 * 10^9 for each verifier and 0.5 * 10^9 for the
registry (measured locally). At the Sepolia gas price of 13 Nov 2026 the whole run comes to about
330 STRK, or about 195 STRK without the aggregate and its verifier.

The registry records the context a proof was made for; it cannot know which context a relying
party issued. The first attestation in a context decides which kind of proof that context takes,
so a relying party keeps a context to itself and the taxpayer until its attestation is recorded.
A scope (taxpayer key, unit, device, year) gets one aggregate per context, even if a later one
would cover more invoices. Nothing is ever withdrawn: what a later spot check finds is for the
relying party to keep. A relying party reads only the attestations in its own context. `submitted_by` is
the account that sent the transaction: a proof is not bound to its sender, so this is information
about the transaction, not about the taxpayer.
